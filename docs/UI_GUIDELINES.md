# 全站 UI 规范

适用于公开页面、个人中心和后台。全站共享视觉语言，但不同页面有不同的信息结构。先确定页面的任务与所属页面族，再选择布局和控件；当前需求与现有页面的事实优先于范例。

## 开始设计前

1. 阅读目标页面，并优先找同业务域两个相近页面或组件，同时检查 `components/layout/PageContainer.vue`、`app.config.ts` 和相关设计变量。若同域实例不足，就找任务最接近的页面族和容器；不要为了凑数量随意类比，也不要只看某张截图就从零生成界面。
2. 在动手前明确五件事：页面容器与宽度、标题层级、区块或列表结构、主要操作位置、字段与弹窗形式。逐一指出准备沿用的现有实现；有意偏离时说明该页面任务为什么需要偏离。
3. 先按任务选参照，不能把某一类页面的排版当作全站默认：

| 页面类型     | 优先查看                                                                                             | 常见误用                                         |
| ------------ | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| 公开内容页   | `pages/links/index.vue`、`pages/partners/index.vue`、`pages/about/index.vue`                         | 直接套后台白色设置卡和工具栏                     |
| 后台资源列表 | `pages/admin/links/index.vue`、`pages/admin/partners/index.vue`、`pages/admin/attachments/index.vue` | 无业务数据却生成仪表盘指标卡、把筛选散放在各卡片 |
| 后台详情编辑 | `pages/admin/users/[id].vue`、`components/admin/users/edit/`                                         | 把所有字段强行改成站点页的横向表单               |
| 低密度设置页 | `pages/admin/site/index.vue`、`pages/me/profile.vue`、`components/profile/edit/`                     | 把两栏、区块保存或字段组件无条件套到其他页面     |

表格只列常见页面类型；登录、授权、首页沉浸式或数据概览等未列页面，应先查目标路由和邻近页面。现有代码是参照，不代表每一处实现都应复制；根据当前任务和明确的产品要求取舍。

## 信息结构与布局

- 先检查 `PageContainer` 选用的容器与页面变体，沿用同页面族的宽度处理，不另造一套页面宽度系统。两个区块只有在任务独立、内容完整且视觉权重接近时才在宽屏排成两栏；窄屏回到单栏。单个区块可以限制宽度并保留留白，不得为凑版式虚构第二张卡或配置项。
- 页面标题、区块标题和辅助文案各司其职。副标题只在提供新信息时出现；不要用“管理某某设置”重复标题。说明文字只解释做决定所必需的规则，避免在卡片下堆放重复的生效时间或状态提示。
- 操作入口贴近它控制的内容。资源列表的创建与筛选放在页首或列表工具栏；只有区块确实能独立持久化时，才参考设置页在各区块标题行保存。同一标题行有管理与保存操作时并排布置，顺序清楚。保存范围必须与实际数据更新范围一致。
- 导航顺序服从信息架构与使用频率。新增入口前检查现有分组及相邻项，不要默认追加到末尾。
- Header 导航使用 `HeaderMenuSurface` 的两层常驻圆角背景：选中态 `sky-300/28`（深色 `/16`），指针预览 `/12`（深色 `/8`），桌面不使用文字下半截的背景和发光阴影。指针预览在真实菜单项与小间距内连续跟随，首次进入先在当前位置准备背景再以 180ms 淡入，移出在末位置淡出，不从上次位置飞入；位移 380ms、宽度 220ms。无外框的空白区域不触发预览。触摸按下提供反馈，超过 8px 的滑动、取消、松手或窗口失焦清理预览，保留原生滚动与点击；键盘聚焦保留预览和原有焦点轮廓。窄屏当前页按钮及弹层中的当前页按钮恢复文字下半截 highlight：高 `0.95em`、宽 `96%`、中心位于 `50% + 0.24em`，使用原有淡蓝背景与轻微阴影，用户页与玩家页带头像时也沿用此尺寸，不占满按钮。桌面用户页与玩家页带头像的菜单背景仍固定为 24px 高并垂直居中，不随头像撑高，包含首次渲染；移动端弹层其他菜单项的指针预览保留完整背景。减少动态效果时关闭背景过渡。
- Header 分类菜单只观察隐藏测量节点、可用空间容器与相邻操作区，不观察跟随 width 动画变化的 nav；同帧的尺寸同步合并执行，逐项宽度未变化时不重写响应式记录。分类切换沿用先退后进，保留原有桌面退场 300ms、入场 460ms、外壳宽度 620ms，移动端退场 300ms、入场 420ms 的节奏。Tailwind 4 的位移工具类使用独立的 `translate` 属性，分类过渡必须包含 `opacity, translate`，不能只写 `transform`，否则位移瞬间跳变；减少动态效果时关闭这些过渡。
- 卡片、标题和留白保持同页面族的表面层级与字重。避免无理由的加粗、过大的标题、过多边框和装饰。个人资料和站点设置的区块标题可参考 `profileSectionTitleClass` 的常规字重；页首标题、资源列表和公开内容有各自层级，不能只改一个全局字号类。
- `/server` 顶部两张地图入口使用可 SSR 的静态卡片，保持上下两张与原有高度；整卡作为外链，左侧放标题和打开操作，右侧放装饰画面。卫星卡片复用八周目地形草图，MTR 使用无站名、无线路数据的装饰 SVG，不作为真实线路图。此处不挂载 BlueMap、WebGL 或实时地图请求，也不使用大面积 backdrop blur；真实地图在用户打开外链后加载。Hover 只以 200ms 遮罩轻微压暗画面，操作文字沿 Slate 中性色变化，边框保持固定，不使用 Primary 色系的交互高亮。

## 用户可见文案

- 标题、按钮、说明和状态文案优先使用简洁、直接的表达。标题说明正在处理什么，辅助文字只补充当前判断或操作所需的信息，不重复标题，不用多个逗号串联已完成步骤和下一步。处理中状态一次只描述当前步骤，例如“正在验证登录状态”“正在保存登录状态”，不额外堆放登录准备、即将跳转等重复说明。
- 文案禁止使用 `·` 分隔信息，优先使用括号，其次使用斜杠。中文文案非必要不使用分号，优先用逗号、句号自然衔接。非必要不使用省略号（`...` 或 `…`），不用省略号装饰加载或等待语气。这些约束针对实际文案，不要求移除具有裁切用途的 CSS 省略效果，也不改写作品名等真实名称。
- 字段标签、必填标识、错误原因和可操作的修正方式保持清楚，不能为了短而只剩“失败”或裸错误码。必要的权限、后果和恢复说明应保留。中英文混排、平台名和专业术语沿用已有拼写与空格，不随意缩写。
- 用户可见文案统一走 i18n，新增、修改或删除 key 时同步所有已支持语言，不能只完成中文。错误 code 与主动抛出的异常使用英语，错误 code 保持大写、下划线风格，面向用户显示对应的本地化说明。具体异常规范见 [文案、i18n 与错误](I18N_ERRORS.md)。

## OAuth 授权与处理中页面

- 授权回调、登录跳转等单步状态页沿用全站字体、主题色票和 `PageContainer` 容器，集中展示一个状态任务。页面底色由站点外壳提供，内部只放一张有圆角、1px 细边框和主题表面底色的卡片，不增加大块局部页面底色、阴影或装饰面板，也不在已有页面容器里重复叠加 `min-h-screen`。
- 处理中卡片可参考 `max-w-md rounded-xl`，边框使用 `border-slate-200 / dark:border-slate-800`，背景使用现有 `surface-0 / dark:surface-1` token。内边距参考 `px-6 sm:px-10 py-10`，内容垂直排列并居中：对应平台 Logo、独立加载圈、较大标题、下一行简短状态说明。容器仍服从本项目的 auth 页面变体和实际路由，不另造宽度体系。
- Logo 外层参考 `size-20 rounded-2xl` 的主题底色和边框，内部图标 `size-10`。加载圈参考 `mt-8 size-6`，标题参考 `mt-6 text-xl sm:text-2xl font-semibold`，说明参考 `mt-1.5 text-sm leading-6` 和次级文字颜色。保留平台标识的原始形态与颜色，使用当前依赖和已有资产，不为这个风格新增组件库或字体。
- 状态文案只描述当前步骤，不写多个逗号拼接的过程说明，不在登录入口额外堆放准备或跳转提示。浏览器标题和导航标题使用明确的本地化任务名称，例如“账号授权”，不落到“当前页”等兜底文案。处理中区域使用 `aria-busy`，状态文字使用 `role="status"` 与 `aria-live="polite"`，减少动态效果时停止旋转。
- 需要用户作出决定的授权同意页保留客户端身份、权限范围、同意与拒绝操作，继续遵循 `pages/oauth/consent.vue` 的任务结构，不能只为套用进度页风格而删去必要的权限说明。可复用状态视图时，将展示与请求、轮询、跳转逻辑分开，平台之间共享布局，通过真实流程更新平台标识和状态。
- 现有路由与组件是实现上下文，不表示它们已经符合本节所有要求。新建或修改同类页面时按本节收敛，不为文档同步顺手批量重写登录与授权业务。

## 全屏背景与页面过渡

- 深浅主题切换由 `useThemeTransition` 和 `assets/styles/base/theme-transition.css` 统一控制，沿用 Intro 的 240ms 整页快照交叠淡化；Header 操作区、主题、语言、用户与导航溢出弹层使用独立的 view-transition-name，直接更新而不参与整页淡化。支持 View Transition 时，无论 Header 下拉是否展开都使用整页快照过渡，不因打开菜单切换成全局颜色插值；仅浏览器不支持 View Transition 或跟随系统切换时使用 240ms 颜色过渡，动画结束清除临时标记；快速切换取消旧过渡，只保留最新选择。首次 hydration 恢复主题不播放动画，避免覆盖页面入场；减少动态效果或后台页面直接切换。主题动画样式仅在 `html[data-theme-transition]` 标记存在时生效，不修改主题底色变量。
- 使用全屏 Blue Map 作为页面背景时，在路由页面的 `definePageMeta` 中声明 `pageBackground: 'map'`。当前首页、公开 Minecraft 玩家档案和个人中心 Minecraft 账号页已接入；普通页面省略该字段，默认解析为 `'none'`。
- 该声明只用于占据整页背景的地图。普通内容区中的 Blue Map 卡片不声明；视频、图片等其他背景目前不接入此策略，需要时先扩展明确的背景类型和解析规则。
- 全屏地图页面的 header 使用固定的深色透明渐变与深色模糊参数，不随全站浅色或深色主题切换。沿用 `resolvePageBackground` 判断地图背景；普通页面及 Minecraft 账号的列表模式仍按主题区分遮罩与模糊参数。
- `utils/layout/page-presentation.ts` 的 `resolvePageBackground` 是唯一解析入口。个人中心 Minecraft 账号页的 `view=list` 必须解析为 `'none'`；动态展示模式通过解析器处理，不让子组件挂载或卸载时抢写全局状态，不维护第二份路由名单，也不通过 DOM 搜索判断背景。
- `app.vue` 维护正在展示的背景和容器状态。涉及全屏地图的页面切换，旧页离场期间保持容器宽度、页头定位和视口模式，离场完成后更新目标页布局并瞬间恢复目标滚动位置，避免旧地图先回顶或被收窄。普通页面使用原有布局更新和平滑滚动；同页面模式切换不得等待不会触发的页面离场事件。
- `PageContainer` 在地图背景模式下不播放宽度与 padding 动画，确保新地图出现时已占满视口；普通容器继续沿用原有尺寸过渡。
- 新增或调整全屏地图页面时，同时核对页面元信息、动态模式解析和实际切页效果；至少检查地图页离开、普通页进入地图、普通页之间切换，以及列表模式。不要为了修复地图过渡而全局修改 `html` 的滚动行为。

```ts
definePageMeta({
	pageContainerVariant: 'immersive',
	pageBackground: 'map',
})
```

## 表单与状态

- 同一页面族的表单保持一致。低密度设置页可参考 `/me/profile` 的横向字段：标签在左、`UInput` 或 `USwitch` 等控件在右；后台用户详情的密集字段参考 `components/admin/users/edit/` 的卡片内两列、标签在上；公开申请弹窗参考 `components/links/FriendLinkApplicationModal.vue` 的任务式表单。字段方向由内容密度与现有页面决定。
- 视觉相似不意味着跨业务共用业务组件。通用 token 或样式类可以复用，字段组件按页面族保留独立调整能力；例如后台站点表单不直接依赖个人资料专用的 `ProfileField`。标签与开关的垂直对齐按所在页面校准，站点设置页可参考 `components/admin/site/` 的 `pt-1`。
- 明确区分未保存草稿与持久化结果。一个区块保存时不要覆盖另一个区块尚未保存的修改；按钮名称、加载态和禁用态应反映实际作用范围。
- 表单使用 Nuxt UI 现有控件及其交互语义，保留可见的字段标签、校验反馈、键盘操作和可理解的焦点顺序。不要为了视觉整齐牺牲输入可用性。

### 表单错误的呈现

- 表单错误必须留在用户正在填写的表单里。字段缺失、格式、长度、图片或文件选择错误显示在对应 `UFormField` 下方，并关联输入控件的错误状态，不能只弹一条通知让用户自己寻找出错位置。表单优先沿用 `UForm` / `UFormField`，字段方向仍按所在页面族决定。
- 提交时一次校验并列出字段错误，将焦点移到首个错误项，客户端校验不通过时不发起提交请求。服务端能定位到字段的错误通过 `UForm.setErrors` 等现有接口回填到字段，不统一吞成一个“提交失败”。必填字段通过 `required` 显示星号，选填字段不标星，保留必要的输入规则和权限说明。
- 网络、权限等无法归属单个字段的错误，在表单内部固定位置持续显示，可使用 `role="alert"` 的可聚焦错误区域，让用户直接看到原因和修正方式。错误不能自动定时消失，失败不能关闭弹窗、清空输入或要求重新填写。修正字段、重新提交或明确关闭表单时，再按对应流程更新或清除相关错误，不因修改无关字段隐藏其他错误。
- 禁止使用 `UNotification` / `UNotifications`、Toast / `useToast`，以及 `notifyError`、`showError` 等会触发悬浮通知的封装承载表单校验、文件选择或提交错误，包括异步请求失败。成功或表单之外的全局反馈按具体交互决定，不能因此把表单失败也交给全局通知。
- 错误出现、更新或消失时保留原表单 DOM、输入值与焦点，只让错误文字做轻微局部过渡，不重播整份表单或弹窗的入场动画。容器可以平滑调整高度，减少动态效果时关闭这些过渡。文件处理中禁止重复提交，非法文件在字段内报错并允许清除或重选。
- 该规范沿用 AurLemon Intro 友链申请表单的反馈方式。Portal 的 `components/links/FriendLinkApplicationModal.vue` 可参考任务结构，但其中已有的通知报错不作为正确范例，新建或修改涉及的表单时按本节逐步收敛。本次规则同步不代表旧表单已完成迁移。

## 弹窗与列表

- `UModal` 一次处理一项明确任务。轻量新增可参考 `pages/admin/site/index.vue` 的字段与底部操作；危险确认参考 `pages/admin/users/[id].vue` 的明确标题、后果说明和确认动作；复杂申请参考 `components/links/FriendLinkApplicationModal.vue`。不要把某一种弹窗结构强加给所有任务。
- 若弹窗只负责新增，已有记录的展示与编辑留在页面或对应列表中，不要把整个管理页面塞进弹窗。
- 弹窗已经有标题时，不要在内容区重复放同义的“新增某某”小标题。保留必要字段、规则提示、错误反馈和明确的取消/确认操作。
- 弹窗内的输入、开关、按钮和间距沿用页面的设计语言；不能因为换了容器就重新发明一套表单样式。

## 视觉实现

- 优先复用 `app.config.ts` 的 Nuxt UI 主题和 `assets/styles/base/tailwind.css` 的 design token。颜色、语义色、字号、表面层级与圆角通过 token 和 class 表达，不在局部硬编码另一套视觉值。
- 卡片先匹配同页面族：个人资料与站点设置常用 `rounded-lg`，后台资源列表也是紧凑的 `rounded-lg`，友情链接卡片使用 `rounded-xl`，伙伴卡片可用 `rounded-2xl`。边框、背景与圆角共同形成层级；不要把任一组 class 当作全站卡片模板。
- 普通布局与视觉使用 Tailwind CSS 和 Nuxt UI。静态样式不要写在 `style` 或 `:style`；`<style scoped>` 留给复杂状态、动画或第三方覆盖，运行时计算值才使用内联样式。
- 不擅自添加 hover 浮动、缩放、强动效或新的重排交互；从当前已确定的视觉方向继续迭代。图标、徽章、渐变和阴影只在同页面族已有模式或内容语义需要时使用，不为“丰富画面”装饰每个标题与操作。

## 修改时的检查

1. 对照需求和截图逐个定位目标区域，确认哪些内容必须保留；纯 UI 请求不新增业务功能或配置项。
2. 删除不能帮助用户判断或操作的副标题、提示、指标、空卡、图标和装饰。检查唯一主操作是否落在合适的标题行或工具栏，而不是孤零零占一张大卡。
